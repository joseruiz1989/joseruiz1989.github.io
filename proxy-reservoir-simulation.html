Executive Summary

The proxy-manager (OctopusIA Proxy Model) is a state-of-the-art Deep Learning surrogate model designed to replace computationally intensive numerical reservoir simulations executed by CMG (Computer Modelling Group) IMEX within the Well Placement Optimization (WPO) pipeline of OctopusIA.

By accelerating full-physics reservoir predictions from hours on an HPC cluster to mere milliseconds on a single GPU, the proxy system enables genetic algorithms to evaluate tens of thousands of well layout configurations, maximizing the Net Present Value (NPV / VPL) of oil fields efficiently.

1. Model Architecture
  • Hybrid Spatio-Temporal Autoregressive Transformer: Combines spatial inter-well Multi-Head Self-Attention with step-by-step autoregressive temporal rollout.
  • Spatial Inter-Well Attention: Sets sequence length equal to active well positions ($L = N_{\text{wells}}$, padded to 20 or 32). Uses torch.nn.MultiheadAttention to model inter-well interference, drainage dynamics, and geological connectivity.
  • Quantized Rate Classification: Converts continuous production/injection flow rates into 1024 discrete ordinal classes trained with Categorical Cross-Entropy via ProxyEmbeddingLayer.
  • Hybrid Loss Function: Blends Categorical Cross-Entropy (with validity masks) for production/injection curves with Mean Squared Error (MSE) for local dynamic state propagation.
  • Modular Multi-Task Decomposition: Managed by ModelUnityManager.py across 4 training phases:
    • BuildProducersCurvesModel (Producer curves)
    • BuildInjectorsCurvesModel (Injector curves)
    • BuildFeaturesModel (Local dynamic reservoir state transition)
    • BuildUnifiedModels (End-to-end unified inference ensemble)
2. Input & Output (I/O) Specifications
  • Static 3D Subvolume (1083 features):
    • $7 \times 7 \times 11 = 539$ local grid cells cropped around perforations (~$600\text{m} \times 600\text{m} \times 200\text{m}$).
    • Net Permeability ($k_h$) and Hydrocarbon Volume per area ($539 \times 2 = 1078$ continuous values).
    • 5 Metadata attributes: Head/completion $(x,y,z)$ coordinates or $(i,j,k)$ grid indices, well type (Producer [1,0] vs Injector [0,1]), and status.
  • Dynamic 3D Subvolume (1078 features): Grid block Pressure and Oil Saturation at timestep $t_1$.
  • Prior Curve State: Discrete class index vectors (0–1023) at timestep $t_1$.
  • Predicted Outputs:
    • Surface Flow Rates (Oil, Gas, Water production, and Water/Gas injection rates in $\text{m}^3/\text{day}$).
    • Local Dynamic Field Update (Updated pressure and saturation fields at $t_2$).
    • Cumulative Volumes via numerical quadrature ($\sum Q \cdot \Delta t$).
Automated CMG IMEX Data Extraction, HDF5 Sub-cube Structuration & PyTorch DataLoaders
3. CMG Integration & Data Pipeline
  • Target Numerical Simulator: CMG IMEX (Black-Oil simulator applied to pre-salt and benchmark reservoirs like Cabo Frio and UNISIM-I).
  • Automatic Parsing: Extracts trajectory and completion data (*PERF (i,j,k)) directly from CMG include files (OctopusWells.inc) via regex.
  • Background CLI Extraction: ReportManagerCMG.py triggers CMG's result.sh tool over binary outputs (.sr3 / .rwd) to serialize intermediate Python .pkl data.
  • HDF5 Space-Time Structuration: generate_h5_data.py reduces full reservoir grids ($4.5 \times 10^6$ cells) to lightweight local 3D sub-cubes:
    • h5_dynamic_base: Static topology and initial state at $t = 0$.
    • h5_dynamic_times: Dynamic state tensors across discrete timesteps ($0, 1, 30, \dots, 7290$ days).

4. Coupling with Well Placement Optimization & VPL

The proxy model functions as a seamless drop-in replacement for CMG during optimization rounds:

  • Drop-in CMG Output Replication: In cmg-inference mode, the proxy generates native-formatted CMG report files (*_proxy_cmg_output.result) matching all headers (TABLE NUMBER, WELL, DATE, rates, cumulative volumes). Economic evaluators read proxy output without modifying a single line of optimizer code.
  • Preservation of Genetic Selection: Evaluated with ranking metrics including Spearman Rank Correlation, Kendall’s Tau, Precision@k, NDCG@k, and selection probability (prob_selec) to ensure genetic roulette/tournament selection is preserved.
  • Massive Computational Speedup: Replaces hours of cluster simulation per individual with milliseconds on GPU, enabling exhaustive search across thousands of well layout candidates per generation.
